:::note[Duende Storage is opt-in and does not replace Entity Framework Core]
Duende Storage is an additional, opt-in persistence option. It does **not** replace the
[Entity Framework Core provider](/identityserver/data/providers/entityframework-core.md), and the classic EF Core schema
(including the `ApiResources`, `ApiScopes`, `ApiResourceScopes`, and related property tables) remains fully supported.
Adopt Duende Storage only if you want the
capabilities described below.
:::

Duende Storage is a relational persistence layer shared by Duende products. IdentityServer adapters connect its
[configuration](/identityserver/data/configuration.mdx) and [operational](/identityserver/data/operational.md) store
interfaces to the storage layer, so IdentityServer continues to use the same abstractions during protocol processing.

## How Duende Storage Works

The provider has four parts:

1. A database-specific package connects Duende Storage to SQL Server, PostgreSQL, Oracle or SQLite.
2. The storage layer persists entities with versioning, indexing and expiration support.
3. IdentityServer adapters implement its configuration and operational store interfaces.
4. Optional administration APIs and schemas let your application manage and extend configuration data.

:::note[Choosing a Database Is Separate from Choosing What to Store in It]
`AddStorage(...)` only selects a database provider for a storage instance; it does not enable storing IdentityServer data by
itself. Call `AddConfigurationStorage()` and `AddOperationalStorage()` to route configuration and operational data to
that instance.

Both configuration and operational stores default to the same storage instance and thus,
one shared database, but each category can target a different instance. See [Multiple Storage Instances](/identityserver/data/providers/duende-storage/multiple-storage-instances.md)
for that setup. To replace one specific store, call an explicit registration such as `AddInMemoryClients()` or
`AddInMemoryPersistedGrants()` after `AddConfigurationStorage()`/`AddOperationalStorage()`. The later registration
replaces only that store and leaves the rest of the Duende Storage setup in place.
:::

## Why Use Duende Storage?

Choose Duende Storage when you need one or more of these capabilities:

* Configuration administration through supported service APIs, without writing directly to database tables.
* Schema-validated custom properties on clients and resources.
* Consistent querying and optimistic concurrency across supported databases.
* Storage pools that isolate data for [Spaces](/identityserver/spaces/index.mdx).
* A shared persistence model across Duende products.

The [Entity Framework Core provider](/identityserver/data/providers/entityframework-core.md) remains a good choice when your
application already uses EF Core and your team wants to manage `DbContext` types, mappings and migrations directly.
[In-memory stores](/identityserver/data/providers/in-memory.md) remain useful for development or deployment-controlled
configuration. A [custom store](/identityserver/data/providers/custom.md) gives you complete control when neither built-in
approach matches your requirements.

## Supported Databases

Duende Storage supports [SQL Server](/identityserver/data/providers/duende-storage/databases/sql-server.md),
[PostgreSQL](/identityserver/data/providers/duende-storage/databases/postgresql.md),
[Oracle](/identityserver/data/providers/duende-storage/databases/oracle.md), and
[SQLite](/identityserver/data/providers/duende-storage/databases/sqlite.md) (SQLite is intended for automated tests
and local development only). See the [databases overview](/identityserver/data/providers/duende-storage/databases/index.mdx)
for packages, registration, and connection strings.
